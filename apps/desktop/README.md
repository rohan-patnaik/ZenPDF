# ZenPDF Desktop

ZenPDF Desktop is the native, account-free workspace for Arch Linux and Omarchy Quattro. It uses C++23 and Qt 6 and does not upload documents or emit telemetry.

## Build

Install Qt 6 Base, Qt 6 PDF, qpdf, CMake 3.25+, Ninja, and a C++23 compiler, then run:

```sh
cmake -S apps/desktop -B build/desktop -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build/desktop
ctest --test-dir build/desktop --output-on-failure
```

Install into a staging root with `DESTDIR=/tmp/zenpdf-package cmake --install build/desktop`. The Arch `PKGBUILD` is a development packaging skeleton; release packages will replace its moving Git source with a signed, checksummed source archive.

## Local data

Qt selects the platform data directory (normally `~/.local/share/ZenPDF/ZenPDF`). On Unix, every native entry path sets umask 077 before Qt starts and requires this application-data leaf to be an owner-owned ordinary 0700 directory before logs or SQLite state are created. Existing database, WAL, and shared-memory files must be owner-owned, single-link regular 0600 files before SQLite opens. ZenPDF safely tightens owner-owned 0755/0644 state that was never group/other-writable; unsafe modes, aliases, types, links, or ownership fail startup closed with a bounded path-free error. This applies equally to direct `zenpdf`, desktop/MIME, and `zenpdf-launch` starts rather than relying on launcher behavior.

The database holds recent paths and timestamps, while bounded diagnostic logs stay under the same private application leaf. Document bytes remain in user-selected paths. Recent-file history can be cleared locally; no account or network connection is required. The automated source tests and remaining installed-package forensic checks are described in `docs/LOCAL_STATE_WAYLAND_ACCEPTANCE.md`. Exact-package private preference save/relaunch, immutable versionless migration, keyboard cancellation, and real Wayland AT-SPI Discard evidence are recorded in `docs/L004_ACCEPTANCE_EVIDENCE.md`.

## Current reader and organizer scope

The installed `zenpdf-launch` command starts the application independently of Quickshell, writes at most 60 KiB of private startup output under the user state directory before draining and discarding later output, and reports a missing executable or early exit without privilege escalation.

The native app opens multiple local PDFs (including password-protected files) in tabs and provides continuous/single-page reading, page navigation, fit/zoom controls, bounded thumbnails, outlines, full-document text search, metadata, recent files, drag-and-drop, bounded local printing, and full-screen presentation. Search exposes a visible accessible status, clears selection and highlight before replacing a query, and has generated regression coverage for Unicode, blank and malformed PDFs, active-search destruction, keyboard traversal, and an 80-page fixture. A hashed opt-in external corpus covers encrypted search, independent-producer Unicode/no-text, malformed recovery, long/result-flood, and sampled hostile resource behavior without shipping hostile PDFs; see `docs/SEARCH_CORPUS_EVIDENCE.md`. Qt PDF provides no public search-completion, cancellation, timeout, result-cap, or resource-budget API here, so the status reports results found so far without claiming completion; `docs/SEARCH_WAYLAND_ACCEPTANCE.md` records the post-publication installed-package gate and remaining limits. Printing is limited to 100 pages per job and a 2048-pixel render dimension; Qt PDF renders each page synchronously, so cancellation takes effect between pages rather than during the current page. qpdf-backed organizer commands merge documents, extract page ranges, delete selected pages, and rotate page ranges into a new file. Extract/delete outputs retain qpdf-supported document-level structure, pass qpdf reopen and expected-page-count checks, and open as a new clean tab; the source tab is never made dirty. Encrypted or permission-restricted organizer inputs are rejected until a separately reviewed password and permission policy exists.

Every document tab owns an in-memory undo stack limited to 512 non-merging commands with clean-revision dirty tracking. Command producers must declare each command's retained payload cost before transfer; a per-session admission gate defaults to 64 MiB and rejects a missing or already-obsolete command, a single over-budget command, arithmetic overflow, or a cumulative over-budget command before execution. Undo and redo retain their declared costs, while replacing a redo branch, Qt obsolete-command removal, and the 512-command oldest-entry eviction release them. Accounting reconciles from the stack's lifecycle signals, including Undo/Redo actions routed through `QUndoGroup`. The non-merging wrapper mirrors the producer's action text after each redo and undo. A command that becomes obsolete during redo is conservatively dirty because it executed without leaving an undo record; an obsolete command removed while undoing follows the resulting Qt clean revision. Queries and rejection/discard signals expose the declared usage, limit, remaining bytes, and an actionable reason for later UI integration.

This is a hard limit on caller-declared retained payload costs, not measured heap use or an allocator-level memory bound. Command object/framework overhead and an inaccurate producer declaration are outside the current accounting, so producer-specific measurement and adversarial validation remain required before a strict memory-bound claim. The Edit menu routes standard Undo/Redo shortcuts to the active tab, dirty tabs receive a visible marker, and tab/application close requires explicit discard confirmation. This is lifecycle infrastructure only: no persistent organizer mutation currently creates commands, and save, save-as, autosave, serialized recovery journals, and crash recovery remain unimplemented.

Each document session also captures a source-revision prerequisite when a stable regular file exists at construction. Explicit owner-thread revalidation reports unchanged, modified, replaced, missing, unavailable, or permanently untracked state and emits only when that status or its actionable diagnostic changes. On Linux the comparison covers the path entry and resolved source device/inode identities, symlink and canonical-path identity, size, and nanosecond mtime/ctime; this detects same-size edits even when mtime is restored and conservatively treats alias-entry replacement as source replacement. A session created without a stable source never adopts a file that appears later. Other platforms use canonical path, size, and available Qt timestamps as best-effort evidence.

This is not continuous monitoring, content hashing, a file-descriptor lease, or a save implementation. It does not close the race after a successful revalidation, and permission/stat failures remain an unavailable state rather than proof that bytes are unchanged. A future atomic save must revalidate again at its publication boundary, preserve the original, and implement the documented write/fsync/validate/replace/recovery sequence.

The shared desktop job-scheduler foundation admits at most two running and 32 queued jobs by default, hard-rejects invalid configuration or excess outstanding work, starts jobs FIFO, and delivers exactly one terminal result on the owning Qt thread in submission order. Queued cancellation prevents execution; running cancellation is cooperative and wins races until terminal delivery. Shutdown rejects new work, cancels queued/running jobs, supports a timed wait result, and the destructor joins remaining work. Task exceptions are isolated into a sanitized 1,024-character failure message.

The modal organizer UI now submits merge, extract, page-deletion, and rotation work through the shared scheduler. Organizer actions are disabled while a job is active, programmatic reentry and scheduler admission failures return actionable errors, and Cancel reaches the same cooperative token consumed by the qpdf adapter. Terminal results are delivered once on the owning UI thread; cancellation discards a stale success payload, while success still opens exactly one clean output tab and leaves the source tab clean. Main-window destruction owns and joins the scheduler lifecycle.

The thumbnail list now defers rendering through an owner-thread FIFO instead of rendering during model data lookup. It admits at most 64 distinct pending pages, renders at 128 pixels wide and at most 512 pixels high, and keeps at most 32 MiB of four-byte-per-pixel cache cost. Repeated requests are coalesced, and a capacity rejection retains only a saturation flag; when a slot drains, a decoration invalidation lets the view re-request currently visible rows without storing an unbounded rejected-page backlog. Failed pages are suppressed until a document reset, and closing or changing a document cancels queued work and clears derived state. Page items expose localized accessible text such as `Page 3`.

This remains a UI-lifecycle foundation, not isolated or background rendering. `QPdfDocument::render` still runs synchronously on its owning UI thread and has no per-page timeout or mid-render cancellation; a hostile or unusually expensive page can therefore block the UI. The 32 MiB figure is a cache admission cost derived from thumbnail pixels, not measured Qt/graphics-driver heap use, and pending requests carry no rendered payload. Long/corrupt producer fixtures, decompression defenses, live memory evidence, retry UX, and real Wayland assistive-technology behavior remain incomplete. Task closures and `QVariant` scheduler results likewise do not have a declared or measured byte budget, and risky future helpers still require process isolation and tree termination.

Organizer commands take private, stable source snapshots, never overwrite a source or existing destination, enforce a 2 GiB input/output ceiling, and apply 100,000-page and bounded-range validation. On Unix, every qpdf phase runs in a separate session, its process group is killed on cancellation or timeout, and stdout/stderr flow through continuously drained bounded pipes. The 120-second deadline is checked between snapshot chunks and while polling helpers; individual filesystem calls and process cleanup can still block beyond it, so whole-job hard wall-clock isolation remains an unsupported edge. Completed results are fsynced, validated, published with an atomic no-replace operation, and followed by a parent-directory fsync. A reported directory-fsync failure means the output was published but its crash durability is uncertain; it does not mean publication was rolled back. Cancellation, timeout, malformed input, validation failure, or a source/destination race before publication removes staging and leaves the source unchanged. Non-Unix process-tree isolation and crash-injection evidence remain missing.

Attachments, form filling, two-page layout, persistent crop/reorder/insert/replace/split, in-place editing, mutation-backed undo/redo, and save/recovery are not implemented yet and remain marked accordingly in the capability matrix. The generated extraction/deletion fixture covers retained text annotations, outlines, metadata, page rendering, and Qt PDF reopen; broad forms, tagged, signed, mixed-box, and independent-producer interoperability evidence is still missing, so the matrix remains `Partial`.
